# ADR-0020: クレジット失効日を締め切りとした期間観測方針への転換（Day 4/5 のコスト最小化制約を組み替える）

## ステータス

Accepted

## 日付

2026-08-22

## 決定内容

- Day 4 以降の実行計画を、「課金を極力抑える」制約から「**消費上限の内側で、時間をかけないと
  取得できない証跡を取り切る**」方針へ組み替える。実行計画の正本は
  [credit-window-execution-plan.md](../operations/credit-window-execution-plan.md)（以下「新計画」）
- 証跡を 2 分類し、扱いを分ける:
  - **(a) 時間が価値を生む観測**（autovacuum 自然発火・bloat 時系列・閾値レンジ・PITR 窓の拡大・
    バックアップ/WAL 推移・SLI・計画メンテ遭遇など）→ **常時稼働で蓄積する**
  - **(b) イベントの計測**（B1ms→GP スケール・HA 有効化・failover）→ **時間を区切り、測ったら戻す**
- 消費に**総上限**を設け（数値はユーザー承認待ち。新計画 §8）、Budget アラート・日次確認・
  優先順位つき打ち切り基準・失効前手順をガードレールとして計画に組み込む
- `/chat` の無認証公開への対処を **(a) 常時稼働の先行ゲート**とする（対処方式はユーザー判断待ち。
  新計画 §10-1）
- 成果物 5 点（Backup / Restore(PITR) / Maintenance / Monitoring / HA）の骨格と、最終 teardown
  （作って測って畳むまでが成果物）は**変えない**

## 背景

### 当初はコスト最小化を制約として設計した

Day 3〜5 の計画（[day3-5-execution-plan.md](../operations/day3-5-execution-plan.md)）は、
「毎日 destroy」「スケールゼロ」「HA は短時間で戻す」など、**課金を極力抑えることを設計制約**として
組んでいた。ADR-0015 / ADR-0017 / ADR-0018 のコスト判断もこの前提の上にある。

### 実測でクレジットが期限付き・大幅に余ることが判明した

2026-08-22 の実測（Microsoft.Consumption lots API、13:10:57Z 取得）で以下が確定した:

- クレジットは "Azure sign-up credit" 200 USD、**2026-09-18T06:59:34Z に失効**する（残り約 26.7 日）
- 現行ペースの消費は最悪ケースでも約 1.5〜2.1 USD/日で、**150 USD 前後が未使用のまま失効する**計算
- サブスクリプションは `FreeTrial_2014-09-01` / `spendingLimit: On`: 超過請求は起きない代わりに、
  **使い切った時点で全リソースが停止**する

つまり「節約」は価値を生まず（余らせて失効しても損失ゼロ）、一方で**使い切りはドリル中の全停止 =
計測記録の喪失**という非対称なリスクを持つ。ユーザー判断（2026-08-22）: 期限内の余裕を観測に使う。
ただし「ぎりぎりまで使い切るのは怖い」— 上限を設けて (b) を膨らませない。

## 検討した選択肢

1. **現行計画のまま（コスト最小化を維持）** — 棄却。autovacuum の自然発火・bloat の鋸歯・
   復元ウィンドウの拡大など、**時間でしか取得できない証跡**を放棄することになる。浮いた
   クレジットは失効して消えるだけで、何も買っていない
2. **クレジットを使い切る方向で最大化（HA を数日間常駐等）** — 棄却。(i) HA を何日置いても
   failover の計測値は良くならない（イベント計測に時間は価値を生まない）。(ii) 使い切りに
   近づくほど「全停止 = 証跡喪失」のリスクを負う。金より証跡が高い
3. **(a)/(b) 分割 + 消費上限 + ガードレール（採択）** — (a) は常時稼働で時間価値を回収し、
   (b) は時間を区切る。上限と打ち切り順序（(b) → OpenAI → (a) の順に止め、(a) と採取済み
   データは最後まで守る）で非対称リスクを制御する

## 影響

- 新計画が旧計画の §4/§5 を置き換える（旧計画は Day 3 の履歴と §2-1/§2-2 の事実台帳として存続）
- 「毎日 destroy しない」（ADR-0018 追記 #84 の 4）は継続。さらに常時稼働の対象が明確化された
- 派生 Issue: #104（マーカー + 観測スナップショット採取）/ #105（Budget アラート = FinOps 成果物）/
  #106（外形監視 SLI）/ #107（/chat 保護 = 先行ゲート）
- ユーザー判断待ち: 総消費上限の額（新計画 §8）と /chat 保護方式（同 §10-1）。
  **どちらかが未決の間は (a) の常時稼働を開始しない**

## 数値の出典

- 単価: Retail Prices API japaneast 2026-08-22 実測（新計画 §1-2。HA standby 同額課金の逐語出典も同節）
