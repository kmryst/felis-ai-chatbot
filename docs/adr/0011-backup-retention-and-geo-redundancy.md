# ADR-0011: バックアップ保持 7 日（既定のまま）・geo 冗長バックアップ無効を作成時に確定する

## ステータス

Accepted

## 日付

2026-08-20

## 決定内容

`terraform/persistent/` の PostgreSQL Flexible Server（`felisaichatbot-pg-dev`）のバックアップ設計を次のとおり確定する。

- `backup_retention_days = 7`（サービス既定と同値。7〜35 日の設定レンジの下限）
- `geo_redundant_backup_enabled = false`

geo 冗長はサーバー作成時にしか決められないため、apply 前のこの時点で判断を確定・記録する。

## 背景

本プロジェクトの本命成果物は「バックアップ・PITR を自分で設計・実行した記録」であり（`docs/operations/day3-5-execution-plan.md` §0）、Day 4 に PITR ドリル（破壊 → 特定時刻へ復旧 → RTO / RPO 実測）を行う。バックアップ保持と geo 冗長は、そのドリルの前提となるサーバー作成時パラメータである。

## 保持期間 7 日の採択理由

**「既定だから」ではない。要件（検証期間 3 日）< 復旧ウィンドウ（7 日）だから採る。**

- 本プロジェクトの検証期間は Day 3〜5 の 3 日間で、PITR で戻る必要がある最遠点は Day 3 のサーバー作成時点。保持 7 日はこれを全期間カバーする
- 保持を延長（最大 35 日）してもカバー範囲の要件は変わらず、バックアップストレージ消費（= 無料枠超過リスク）を増やすだけで得るものがない。無料枠はプロビジョン済みストレージの 100%（本サーバーでは 32 GiB）であり、超過分から GB/月課金が始まる
- 保持期間は作成後もオンラインで変更可能（7〜35 日）なので、この判断は可逆であり、将来要件が変われば変更できる

## geo 冗長バックアップ無効の採択理由

1. **有効化はサーバー作成時のみで、作成後は変更不可。** だからこそ「今」判断して記録する必要がある（不可逆な判断）
2. **有効時はバックアップストレージ消費が 2 倍で課金される。** FreeTrial クレジットで運用する本プロジェクトでは純減
3. **geo リストアは PITR 不可（最新復元のみ）で RPO は最大 1 時間。** 本プロジェクトの本命である「任意時刻への PITR ドリル」には一切寄与しない
4. **リージョン災害対策（geo 冗長が本来解く問題）は本プロジェクトの要件にない。** 検証用 dev 環境であり、Day 5 終了時に destroy する

## 検討した選択肢

1. **保持 7 日 + geo 冗長無効**（採択）
2. 保持 35 日 + geo 冗長無効（却下: カバー要件は 7 日で満たされ、バックアップストレージ消費と無料枠超過リスクだけが増える）
3. 保持 7 日 + geo 冗長有効（却下: 上記のとおり 2 倍課金で、PITR ドリルにも要件にも寄与しない。「不可逆だから念のため有効」はコストに見合わない）
4. 長期保持（Azure Backup / LTR）の併用（却下: 計画書 §9 のスコープ外。要件（3 日）に対して過剰）

## 影響

- Day 4 の PITR ドリルは、保持 7 日ウィンドウ内の任意時刻復元として実施する
- geo 冗長を後から有効にしたくなった場合はサーバー再作成が必要（この ADR を supersede する判断になる）
- 「保持期間はどう決めましたか？」への回答は本 ADR が正本（想定追い質問と成果物の対応は計画書 §0-2）

## 数値の出典

- 既定 7 日・設定レンジ 7〜35 日・作成後のオンライン変更可・geo 冗長は作成時のみ・geo 有効時はバックアップサイズ 2 倍課金・バックアップ無料枠 = プロビジョン済みストレージの 100%: [Backup and restore in Azure Database for PostgreSQL flexible server](https://learn.microsoft.com/en-us/azure/postgresql/flexible-server/concepts-backup-restore)（2026-08-19 に確認。計画書 §2-1 No.1 / No.5 / No.7）
- geo リストアの RPO 最大 1 時間・PITR 不可（最新復元のみ）: 同上（計画書 §3-1 geo 冗長の行）
- PITR の実 RTO / RPO は本 ADR 時点では**未実測**。Day 4 のドリルで実測し `docs/verification/restore-drill/` に記録する
